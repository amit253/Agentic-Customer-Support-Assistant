## 5. Architecture: one guarded service for text and voice

Read left to right. Both channels enter the same SupportService. Nothing reaches the router or any agent before validation and the input guard; every reply leaves through the output claim guard. Dashed lines are dependencies. Conversation agents have no retrieval or tools.

## 6. Every step fails safe, and none of them fails silently

This is the end-to-end trace the assignment asks for. Running the guard and the router in parallel was considered and rejected because the router LLM would then see unchecked text.

Sources: src/agentic_support/pipeline.py; tests/test_step5_call_path.py; tests/test_conversation.py

## 7. Hybrid routing: the LLM only when needed

Rules decide 54 of 110, labeled examples 29, the LLM 27. A test fails if any training example appears in the held-out set. The semantic tier answers only when the best intent beats the runner-up by 0.15 cosine; that margin gave precision 1.00 at 44% coverage in leave-one-out.

Sources: reports/phase2-hybrid-live-evaluation.md (routing sources); docs/router-design.md

## 8. Routing results on 110 held-out messages

Per-intent precision and recall on the held-out set. 'Outcome' counts a no-route result as correct only when the clarifying reply is the right answer. Remaining misses: 'the blue one' gets a clarifying question; 'xkcd lorem ipsum' is called off-topic instead of unclear.

Sources: reports/phase2-hybrid-live-low-effort-evaluation.md

## 9. Retrieval: fuse meaning and keywords, gate for recall

Why this embedding approach: e5 is multilingual (Hinglish) and fused with BM25 for exact product names. Cross-encoder rerankers were tried and dropped: their dev-tuned gate did not transfer and they cost about 0.5 s per query on CPU.

Sources: reports/retrieval-comparison.md; reports/final-retrieval-offline-evaluation.md

## 10. Grounded answers: two gates and a claim check

The retrieval gate cannot separate near-misses like 'Trailmark price' from real questions, so it favors recall and the answerer is the precision gate: it declined all 13. One correct negated answer is blocked by the claim guard; that is an open finding.

Sources: reports/final-rag-live-evaluation.md; reports/red-team-live-probes.jsonl

## 11. Order agent: the model chooses, the application decides

Ownership is enforced by the tool with the server-side session's customer ID. Cancel and refund requests are answered honestly with verified facts and a human route.

Sources: src/agentic_support/tool_calling.py; handlers.py; tools.py; tests/test_order_actions.py

## 12. Memory and handoff: one session across voice and text

Raw transcript text is never sent to a model, so an earlier message cannot inject instructions later. The store is process-local; production needs Redis for live session state and Postgres for transcripts, with retention and encryption.

Sources: src/agentic_support/memory.py; catalog.py; docs/memory-handling.md

## 13. Voice line: barge-in that cannot double-handle a turn

Every scenario uses the user's own recordings. The coordinator only accepts a result for the current turn ID, so a late STT result for a cancelled turn is discarded rather than spoken.

Sources: recordings/final-*-run.json; scripts/run_voice_coordination.py; docs/voice-coordination.md

## 14. Voice latency: speech turns answered in 2.1–2.9 s

Target is under 3 seconds from end of speech; the speech turns measured 2.12 to 2.95 s and the local failure handoff 0.54 s. The margin is thin, so it is stated as measured, not as an SLO.

Sources: recordings/final-*-run.json; docs/voice-coordination.md (Final measured runs)

## 17. Path to 10,000 concurrent sessions

Measured fact behind the degrade story: with the LLM tier removed, the local tiers still reached 77% outcome accuracy offline. Switching providers changes behavior, so a failover model must pass the same eval sets before it can take traffic.
